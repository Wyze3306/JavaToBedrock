# Mapping data: sources and licences

## resourcepack/ (resource pack converter)

Generated by `tools/gen_resourcepack_tables.py` (Python 3, standard library only) from:

| File | Content | Sources |
|---|---|---|
| `textures.json` | Bedrock vanilla texture path -> Java vanilla texture(s) it replaces one to one, with the Java frame size (aspect-ratio check of server overrides) | inverse of GeyserMC PackConverter's texture mappings (MIT) + identical paths + pixel-equal images + unique same-stem matches, keeping only pairs whose vanilla images have the same size and no tint-mask / stitched textures; computed against Mojang `bedrock-samples` v1.26.50.4 and the Java 26.3 client assets (mcmeta). Input file: `texture_overrides_safe.json` of the r8 research scripts |
| `atlases.json` | vanilla `terrain_texture.json` / `item_texture.json` short names -> texture paths (only names with a mapped texture) | Mojang `bedrock-samples` v1.26.50.4 `resource_pack/textures/` |
| `flipbooks.json` | vanilla Bedrock flipbook animations by texture | `bedrock-samples` `resource_pack/textures/flipbook_textures.json` |
| `sound_files.json` | Bedrock vanilla sound file -> Java vanilla sound file(s) | inverse of GeyserMC PackConverter `mappings/sounds.json` (MIT) + identical paths, against `bedrock-samples` sounds and Java 26.3 `assets/minecraft/sounds` |
| `carrier_blocks.json` | Java blocks usable as custom-block carriers: properties in Java order and the vanilla blockstate file | Java 26.3 block state summary and `assets/minecraft/blockstates` (mcmeta) |

No game asset (texture, sound, model) is redistributed: the tables only hold paths, sizes, frame
lists and blockstate model references. Regenerate after a game update:

```bash
python3 tools/gen_resourcepack_tables.py --safe texture_overrides_safe.json \
    --sounds bedrock_to_java_sound_files.json --bedrock bedrock-samples/resource_pack \
    --java 26.3-assets/assets/minecraft --blocks 26.3-summary/blocks/data.json
```

The converter also ports code from GPL-3.0 projects (licence-compatible with JavaToBedrock):
pack decryption from ViaBedrock (`ResourcePack#decryptContent`, RaphiMC) and the Bedrock geometry
conventions of CubeConverter (oryxel1) / Blockbench, with their known bugs fixed (inflation applied
to one side only, bone mirror/inflate and bone rotations ignored, glyph page FF skipped, attachable
key mismatch, non lower-cased identifiers).
