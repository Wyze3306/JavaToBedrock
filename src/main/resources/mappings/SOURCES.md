# Mapping data sources

Every generated table under `src/main/resources/mappings/` records where it comes from. Regenerate with the
tool named in each section (Python 3, standard library only) against the pinned inputs.

## sound/ (sounds, particles, level events)

Generator: `tools/gen_sound_mappings.py` (`python3 -I tools/gen_sound_mappings.py --ref <dir with the clones>`).

| File | Content | Sources |
|---|---|---|
| `sounds.json` | Bedrock sound name (`sound_definitions.json` key, PlaySound) -> Java 26.3 sound event + Java category | ViaBedrock `custom/sound_mappings.json`, `bedrock/sounds.json`, `custom/sound_category_mappings.json`; categories cross-checked with Mojang bedrock-samples `sounds/sound_definitions.json` |
| `sound_events.json` | LevelSoundEvent string -> entity / block-sound-type / generic variants (Bedrock sound, volume and pitch ranges); block -> sound type; note block instruments | ViaBedrock `bedrock/level_sound_event_mappings.json`, `bedrock/block_sounds.json`, `custom/note_block_instrument_mappings.json` (themselves derived from bedrock-samples `sounds.json` / `blocks.json`); bedrock-samples `blocks.json` |
| `particles.json` | SpawnParticleEffect identifiers and LevelEvent particle types (Bedrock wire id) -> Java particle with data | ViaBedrock `custom/particle_mappings.json`, `custom/level_event_particle_mappings.json`, `bedrock/particles.json`, ViaBedrock `ParticleType` enum (wire ids); hand-written replacements (generator) for particles MCProtocolLib cannot write and for ids ViaBedrock leaves unmapped |
| `level_events.json` | LevelEvent (Bedrock wire id) -> Java level event / sound / particle | ViaBedrock `custom/level_event_mappings.json` and its `LevelEvent` enums (Bedrock and Java wire ids); hand-written overrides (generator) |

Java ids are validated against MCProtocolLib 26.3 (`BuiltinSound`, `ParticleType`, `LevelEventType`, MIT) and
ViaBedrock `java/via_mappings.json` (26.3 block state and item ids, same order as the vanilla registries).
Bedrock enum names differ between ViaBedrock and the protocol library, so level events and particle types are
keyed by numeric wire id and joined at run time through the codec's type maps (`sound.BedrockIds`).

Pinned inputs: ViaBedrock `c765b78` (2026-10-19, GPL-3.0), MCProtocolLib `b4fa8b2` (26.3, MIT),
Mojang bedrock-samples `46ba6ea9` (1.26.50.4, Minecraft EULA: only names and numbers are used).
JavaToBedrock is GPL-3.0, which allows shipping tables derived from ViaBedrock's data.

## Player (`effects/bedrock_effects.json`, `player/instant_break.json`)

Generated by `tools/gen_player_mappings.py` (Python 3, stdlib only).

| File | Content | Sources | Licence |
|---|---|---|---|
| `effects/bedrock_effects.json` | Bedrock mob effect network id → Java 26.3 mob effect key (`fatal_poison` → `poison`, `village_hero` → `hero_of_the_village`) | GeyserMC `core/src/main/java/org/geysermc/geyser/level/EffectType.java` (commit 02dbfac), cross-checked against PowerNukkitX `entity/effect/EffectType.java` | MIT (Geyser); ids are protocol facts |
| `player/instant_break.json` | Java 26.3 block state id ranges whose block has destroy time 0 (broken instantly in survival: the Java client predicts the break on START and never sends FINISH) | destroy times: GeyserMC `core/.../level/block/Blocks.java`; state order: ViaBedrock `data/java/via_mappings.json` (`blockstates`, 35723 states, checked equal to Geyser's registration order) | MIT (Geyser), GPL-3.0 (ViaBedrock) |

# Mapping data: sources and licences

## resourcepack/ (resource pack converter)

Generated by `tools/gen_resourcepack_tables.py` (Python 3, standard library only) from:

| File | Content | Sources |
|---|---|---|
| `textures.json` | Bedrock vanilla texture path -> Java vanilla texture(s) it replaces one to one, with the Java frame size (aspect-ratio check of server overrides) | inverse of GeyserMC PackConverter's texture mappings (MIT) + identical paths + pixel-equal images + unique same-stem matches, keeping only pairs whose vanilla images have the same size and no tint-mask / stitched textures; computed against Mojang `bedrock-samples` v1.26.50.4 and the Java 26.3 client assets (mcmeta). Input file: `texture_overrides_safe.json` of the r8 research scripts |
| `atlases.json` | vanilla `terrain_texture.json` / `item_texture.json` short names -> texture paths (only names with a mapped texture) | Mojang `bedrock-samples` v1.26.50.4 `resource_pack/textures/` |
| `flipbooks.json` | vanilla Bedrock flipbook animations by texture | `bedrock-samples` `resource_pack/textures/flipbook_textures.json` |
| `sound_files.json` | Bedrock vanilla sound file -> Java vanilla sound file(s) | inverse of GeyserMC PackConverter `mappings/sounds.json` (MIT) + identical paths, against `bedrock-samples` sounds and Java 26.3 `assets/minecraft/sounds` |
| `carrier_blocks.json` | Java blocks usable as custom-block carriers: properties in Java order and the vanilla blockstate file | Java 26.3 block state summary and `assets/minecraft/blockstates` (mcmeta) |

No game asset (texture, sound, model) is redistributed: the tables only hold paths, sizes, frame
lists and blockstate model references. Regenerate after a game update:

```bash
python3 tools/gen_resourcepack_tables.py --safe texture_overrides_safe.json \
    --sounds bedrock_to_java_sound_files.json --bedrock bedrock-samples/resource_pack \
    --java 26.3-assets/assets/minecraft --blocks 26.3-summary/blocks/data.json
```

The converter also ports code from GPL-3.0 projects (licence-compatible with JavaToBedrock):
pack decryption from ViaBedrock (`ResourcePack#decryptContent`, RaphiMC) and the Bedrock geometry
conventions of CubeConverter (oryxel1) / Blockbench, with their known bugs fixed (inflation applied
to one side only, bone mirror/inflate and bone rotations ignored, glyph page FF skipped, attachable
key mismatch, non lower-cased identifiers).

## entity/ (entity types, entity data indices, hit boxes)

Generator: `tools/gen_entity_mappings.py` (`python3 -I tools/gen_entity_mappings.py [--viabedrock DIR] [--geyser DIR] [--mcpl DIR]`).

| File | Content | Sources |
|---|---|---|
| `entities.json` `bedrock_to_java` | Bedrock entity identifier -> Java 26.3 entity type (`null`: vanilla Bedrock entity without Java equivalent, not shown) | ViaBedrock `custom/entity_mappings.json` |
| `entities.json` `classes` | Java entity data classes (parent, then field names and MCProtocolLib metadata types in index order) | field names: ViaBedrock `java/entity_data_fields.json`; class hierarchy written out in the generator (vanilla 26.3); field types and counts: Geyser `VanillaEntities.java` (each type's field count is checked against Geyser, a mismatch fails the generation) |
| `entities.json` `java_types` | Java type -> data class, hit box, Bedrock position offset (how far above the Java position Bedrock moves place the entity) | Geyser `VanillaEntities.java` (`width`, `height`, `offset`); `block_display`/`item_display` and the falling block / boat offsets hand-written in the generator (PowerNukkitX values) |
| `entities.json` `paintings` | Bedrock painting motive -> Java `painting_variant` | ViaBedrock `custom/painting_mappings.json` |
| `entities.json` `effects` | Bedrock effect id -> Java mob effect | ViaBedrock `bedrock/effects.json`, `custom/effect_mappings.json` |
| `entities.json` `damage_causes` | Bedrock `ActorDamageCause` (index) -> Java `damage_type` (hurt animation of `ActorEvent HURT`) | ViaBedrock `custom/damage_cause_mappings.json` |
| `entities.json` `boat_variants` | Bedrock boat `VARIANT` -> Java boat wood | PowerNukkitX boat wood order (hand-written in the generator) |

Pinned inputs: ViaBedrock `c765b78` (GPL-3.0), Geyser `02dbfac` (MIT), MCProtocolLib `b4fa8b2` (26.3, MIT; `EntityType`
order and metadata type names). Villager professions/types, axolotl variants and the armor stand pose table are
small hand-written tables in `entity.ActorDataTranslator` (inverse of Geyser's entity setters, MIT); wolf, cat and frog
variants are resolved at run time by name in the Java registries.
